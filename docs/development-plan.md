## 1. 项目目标与首版范围

### 1.1 已确认的项目定位

开发一个本地运行的 CLI Agent，通过自然语言对话完成 Bangumi 查询、个人收藏管理、进度更新和作品推荐。

CLI 产品名称为 `MyBangumiAssistant`，npm 包名为 `my-bangumi-assistant`，可执行入口名为 `my-bangumi-assistant`，保留 `bangumi-agent` 命令别名。改名保留现有源码目录、默认用户数据目录和 `BANGUMI_AGENT_*` 环境变量，继续读取已有配置、会话及登录数据。

项目以自用起步，保留后续开源和扩展空间。Harness 借鉴 deepseek-harness 的分层设计，自建轻量核心。

### 1.2 已确认的功能范围

| 功能 | 首版范围 |
| --- | --- |
| 搜索、详情 | 动画、书籍、音乐、游戏、三次元 |
| 收藏管理 | 所有类型；具体字段和操作集合后续细化 |
| 进度查询与更新 | 对所有类型展示原生能力；动画/三次元支持单集，书籍支持章数/卷数，音乐/游戏当前接口拒绝细粒度写入 |
| 个性化推荐 | 优先围绕动画实现 |
| 对话操作 | 支持连续对话、作品指代和多步骤任务 |
| 模型接入 | 一种兼容协议，支持多个模型配置和手动切换；首个测试提供方为 DeepSeek |

### 1.3 已确认的首版排除项

- 不包含社区功能，包括讨论、日志、动态、通知及相关发布操作。
- 不包含本地补充进度，例如额外的游戏路线、游玩时长、自定义完成百分比等。

“不做本地补充进度”不影响本地保存会话、操作记录和查询缓存；这些数据属于运行支撑数据。

### 1.4 代表性使用场景

- “找一下葬送的芙莉莲，看看有哪些关联作品。”
- “把刚才第二部加入想看。”
- “这部评分改成 8 分。”
- “昨晚看到第 8 集了。”
- “这本书读到第 3 卷了。”
- “从我的想看里推荐几部科幻动画，排除已经看过的作品。”

这些场景用于后续制定验收用例；尚不代表接口和进度语义已经全部确定。

### 1.5 已确认的对话任务边界（2026-10-02）

- 按用户最终任务目标划定范围，范围内继续由模型自由组合已登记工具，不为每种请求写死执行流程。
- 允许五类作品查询、比较、基于已取得资料的简短讨论/统计、个人收藏与网站原生进度、个人收藏短评草稿、动画推荐，以及本助手安装配置使用咨询、简短礼貌交互。观看规划中的简单计算属于辅助任务；独立数学解题、编程、办公或生活咨询不属于范围，借作品作背景也不能改变任务性质。
- 社区发布/回复/日志/动态/通知、定时任务/提醒、本地补充进度和跨账户操作属于首版排除项。作品名或待保存正文中的“数学”等词不构成越界证据；例如《数学女孩》查询允许，数学解题拒绝。
- 返回分为正常处理、明确越界、范围内能力不足、需要澄清、混合任务。现存五类收藏列表、媒体/状态筛选、完整收藏统计已向模型提供只读能力；包括已删除记录的完整观看历史及长期偏好尚未提供，明确说明缺失。可以基于现存收藏或已核实作品查询并尝试推荐，不将本次读取扩展当作M5完成。
- `ask/chat` 经宿主入口分流：完整匹配的选择/补值/确认/取消及明确修改仍使用现有规则和权限；少量完整无关命令直接本地拒绝；其他自由表达由用户当前选择的同一模型做无业务工具的受限JSON分类。宿主校验类别及原文片段，再选择固定拒绝、能力说明、澄清或进入业务循环。分类正文/思考不展示、不进入日志；分类失败不跳过边界，不调用业务工具，取消保持取消结果。
- 混合任务先说明不处理的部分，模型仅接收可独立处理的原文片段。片段必须有序且不重叠，不能新增或改写任务；完整真实原文仍用于日志及工具权限，不能用分类片段取得直接授权。写入及确认仍按第5节规则，不改变账户/对象/参数绑定。
- 拒绝、能力不足、澄清或分类失败时清除未完成修改及待确认授权；明显切换话题后旧预览不能继续确认。日志保留原文，后续回答模型及候选恢复使用宿主允许的片段/标记，不继续回答旧的越界内容。JSON结果增加 `boundary.code`，固定回退是正常对话结果。
- 额外分类请求会增加部分自由表达的延迟和模型用量。当前只有离线分类协议、分流和权限验收；语义判断可能误判，真实模型分类质量与完整人工chat需单列联调，不承诺完美识别所有越界表达。

### 1.6 已确认的五类收藏列表与统计（2026-10-02）

- 读取当前登录账户的书籍、动画、音乐、游戏和三次元现存收藏，包含该账户有权读取的私密收藏；不能指定第三方账户，不包含已删除收藏历史。
- `list_collections` 提供媒体/收藏状态筛选和最多20项的偏移分页；`get_collection_summary` 自动完整读取所需范围，在宿主本地计算总数、五类数量、五种收藏状态及个人评分分布。CLI对应 `collections` 和 `collection-summary`，无需模型也可使用。
- 已完成按网站条目收藏状态统计，分别表述为读过/看过/听过/玩过，不从章节进度推断。个人评分1～10分分别计数，0单列为未评分；缺失或异常为未知，均不混入平均分，显示有效评分样本数。空列表返回零值；限定媒体时其余类别不返回未查询的零值。
- 完整读取每页100项、上限100页/10000项，检查总数、分页数量、重复、筛选范围及账户，完成后再次核实账户。缺页、总数变化、错误、超时或取消不返回局部全量统计。分页通过不等于网站原子快照；注明读取范围及时间。
- 收藏记录包含ID、媒体类型、名称、状态、个人评分、标签、原生进度、可见性及可取得的更新时间，缺失保持未知；不附带短评、作品简介或凭据。完整列表仅在请求内存供统计/未来推荐筛选，模型和会话只取得汇总或必要的一页，不新增持久缓存或长期偏好。
- 读取适配沿用当前OAuth认证和固定本人收藏GET端点，不依赖上游身份探测失败后的公开列表回退；写入现状核实和回读继续独立实时读取。开发及离线验收已完成，真实账户和模型联调单列待验证，M5继续暂缓。

## 2. 已确认的技术方向与架构建议

### 2.1 已确认

- Bangumi 操作基于 bgm-cli。
- 自建轻量 Harness，借鉴 dsh 的模型循环、工具策略和会话日志设计。
- 模型接入采用一种兼容协议，保存多个模型配置，由用户手动切换。
- 允许按任务需要向模型发送必要的个人数据。
- 首个测试模型提供方为 DeepSeek，可以利用现有 Claude Code 配置中的接入信息。

### 2.2 建议采用的模块边界

| 模块 | 职责 |
| --- | --- |
| CLI 层 | 输入、流式输出、候选选择、操作预览、取消和历史会话入口 |
| Harness 层 | 模型循环、上下文组装、工具调用、任务边界和会话恢复 |
| 领域工具层 | 搜索、详情、收藏、进度和推荐能力 |
| bgm-cli 与 OAuth 适配层 | 固定桥接复用锁定客户端的数据转换；OAuth Bearer 认证、回调、刷新及错误与结果归一化；条目取消收藏暂停 |
| 本地存储层 | 会话、操作记录、缓存；长期偏好是否保存尚待确认 |

模型面向明确的领域工具。参数校验、权限判断、进度规则和写入验证由代码负责。

### 2.3 工程约定与其他建议

目录结构和工程基线已在根目录 AGENTS.md 中约定：Node.js + TypeScript + ESM、单包项目、npm，优先保证 Windows 本地使用顺畅；具体运行时与依赖版本在工程初始化时核实并锁定。

以下实现建议仍可在后续设计中调整：

- 固定 bgm-cli 依赖版本，通过参数数组调用子进程，避免拼接 shell 命令。
- CLI 输出与 Agent 核心分离，后续可以增加其他交互界面。
- 首版优先单账户，不加入定时任务和跨账户操作。
- 默认自动读取运行电脑的代理配置；本机 Clash 地址为 `http://127.0.0.1:7890`，但不固定其他电脑的端口。详细规则见2.5节。

### 2.4 已确认的终端交互（2026-10-02）

- 用户批准参考 Codex CLI 的对话布局：正常终端回滚区保存已完成记录，底部动态区域集中显示执行状态、草稿和菜单。保持轻量 TypeScript 单包；界面采用 Ink 7.1.1 / React 19.2.0，基础 Markdown 使用 marked 17.0.1，字素与显示列宽分别由 Intl.Segmenter / string-width 8.1.0 处理，TSX 纳入现有构建。
- 启动顶部参照 Claude Code 的无边框布局：左侧为用户提供的 Bangumi SVG 预转换粉色字符图，缩小为12列×6行；右侧第一行 `MyBangumiAssistant v版本号`（版本来自 package.json），第二行 `当前模型：实际模型名`，第三行 `当前Bangumi用户：username`。无有效本机登录时，第三行显示“当前未登录Bangumi账号”；账户名使用 Bangumi 的 username 而非昵称或数字ID。宽窗口左右排列，窄窗口上下排列并按字素换行，极窄窗口省略图标；普通文本和非TTY回退只显示三行文字。
- 启动及 `/status` 的在线检查最多8秒；保存登录且只读数字账户一致后使用网站返回的username。网络/账户错配等无法确认时使用本机保存的username并明确标注“登录状态待核实”，不冒充登录成功或未登录。组件只取得账户ID和用户名，不取得 Cookie、UA 或保护后的凭据；字符图运行时不需要浏览器或图片处理。
- 完整横幅仅用于启动；登录成功和切换模型/会话输出精简的一行模型/账户更新（窄窗口自动换行），底部持续显示当前模型和登录状态，不显示会话ID。
- 命令列表加入 `/login`，宿主在日常默认浏览器打开 OAuth 授权并监听固定回环回调。浏览器已有登录时点击授权即可自动返回；授权码交换为 Token 并核实 API 账户后保护保存，可重新授权或切换账号。开始登录即清除旧预览及未完成修改；失败或保存前取消保留原本机认证。登录不经过模型、不采集 Cookie；Esc/Ctrl+C取消。
- `/status` 单独输出带字段名的状态清单：Bangumi登录及本次只读核实结果/失败原因、实际模型名、本地模型配置名称、完整会话ID及恢复用途、当前作品焦点、待确认变更条目数/预览ID/展示状态、结果未知操作数及先核查不重试的提示。无待确认/未知项分别明确为“无”/“0项”。不重复顶部卡片，不请求模型或写入账户，不使原待确认预览失效。
- 输入支持中文字素编辑、有限输入历史、多行草稿与粘贴；Enter 发送、Ctrl+J 换行，支持的终端可用 Shift+Enter。执行时可编辑下一轮草稿，禁止并发提交，不自动排队。命令候选、候选菜单、模型/会话菜单均由宿主处理；选择候选继续既有消歧与跨轮请求。
- 用户批准命令输入直接交互：单行输入 `/` 立即在输入框上方显示列表，默认高亮第一项；↑↓直接选择、Tab只补全、Enter执行当前高亮的完整命令。始终可打字、退格和移动光标，修改后优先精确匹配，再保留仍匹配的高亮项，否则回第一项；不进入独立的命令选择模式。列表最多6项，随高亮滚动，窄窗口裁剪说明并保留完整命令名。Esc仅隐藏候选并保留草稿，输入变化后重新显示；无匹配单行命令本地提示并保留草稿，不交给模型。参数区不参与命令替换，保留已有完整参数快捷入口，缺必要参数提示用法；多行和正文中的斜杠仍按普通草稿处理。输入历史保存实际提交的完整命令；运行时保留草稿且不能执行，Esc/Ctrl+C仍取消本轮。作品、模型、会话菜单与原宿主权限/回读保持原链路；普通文本回退不提供按键候选。
- 作品消歧参考 Codex 的结构化用户提问交互：模型调用 `request_subject_selection` 提出简短问题，宿主固定候选及顺序，结束本轮等待真实用户回答；终端自动显示选项，空草稿时方向键和Enter选择，或输入编号、完整名称及已有自然选择句式，回答后立即继续原查询。Tab仍可打开候选菜单，普通文本与ask续接使用同一宿主链路。选择不授予修改权限；明确修改的缺失对象仍由原确定性请求补全，恢复不重放未完成修改。并非接入Codex服务或复制其Harness。
- 个人收藏查询与进度工具同时给出数字状态和宿主映射的 `statusMeaning`：1计划、2已完成、3进行中、4搁置、5抛弃；动画2是看过、3是在看。模型按字段事实回答，不从已看集数或评分推断状态，不混用章节枚举。真实模型回答质量仍需单独验证。
- 复杂操作的完整预览进入终端后，renderer 等待输出 flush 再登记 ID/摘要；确认卡默认取消。按键确认、自然确认与 `/confirm` 均走原宿主权限链路。明确单项不增加确认；模型/会话切换、取消和恢复均使旧预览失效。
- 每轮取消与会话退出分开：运行时 Esc / Ctrl+C 停止本轮，菜单中 Esc 返回，空闲时两次 Ctrl+C 或 `/exit` 退出。写入已发送时等待原执行器的独立回读结束，保留成功/失败/未知/未开始及附带进度结果，不自动重发。
- 核心输出不含凭据/推理的结构化模型与工具活动事件；执行器报告实际提交/回读阶段。界面统一展示中文活动与结果，基础 Markdown 表格按宽度切换，外部文本不能注入终端控制序列。活动区刷新有界，长回答最终完整进入历史。
- `chat --plain` 保留单行文本回退；非TTY输出与 TERM=dumb 自动回退。`ask` 和 JSON结构继续兼容。离线模拟终端验证与真实 Windows 终端/模型/账户验收分开，后者尚未执行。

用户最新已确认：先实施 OAuth 主登录，条目取消收藏暂不开放；撤回专用浏览器 Cookie 主登录和删除入口，不实施 Cookie 扩展桥接。查询、收藏字段及原生进度继续使用 OAuth Bearer。历史讨论保留在[登录流程方案](login-flow-proposal.md)，当前实现及配置见 README。

### 2.5 已确认的自动代理发现（2026-10-02）

- 用户批准自动沿用运行电脑的代理环境，优先级为显式应用 proxy（null明确直连）→ BANGUMI_AGENT_PROXY → 标准 HTTP/HTTPS 代理变量 → Windows 当前用户系统代理 → 直连。无需保存当前电脑的探测结果；配置示例省略 proxy 以启用自动发现，不扫描或固定7890端口。
- 标准变量小写优先，按目标协议分流并遵守 NO_PROXY；Windows 固定代理支持普通地址、分协议地址及绕过列表。macOS/Linux 使用应用/标准环境变量；PAC/WPAD 脚本、SOCKS和ALL_PROXY暂不解析，检测到不支持配置或系统读取失败时明确报错，不静默选择另一条线路。
- 模型、Bangumi 查询/写入子进程及 OAuth Token 交换共享启动时解析的策略快照；授权页使用日常浏览器自身网络设置，本应用不修改浏览器代理，回环回调直连。doctor 和 /status 展示来源、地址和实际路由，配置变化需重启应用。
- 代理请求失败不自动改代理、切换直连或重新提交写入。现有账户权限、取消与独立回读规则保留；需要登录时的固定回退及模型同轮停止策略仍属于6.1.1节待实施方案。
- 开发与137项全量离线验收完成，新增13项覆盖跨端口配置、系统发现、协议/绕过、真实本地CONNECT传输、子进程策略快照和实际read-worker的代理拒绝。当前本机标准环境与系统代理读取已核实，匿名公开搜索自动走代理成功；其他操作系统实机及真实登录浏览器尚未验证。

## 3. 进度模型


### 3.1 已确认原则

- 首版支持所有媒体类型的进度查询和更新。
- 仅处理网站原生进度，不增加本地自定义进度字段。
- 不同媒体类型采用符合实际含义的进度表示，不将所有类型统一解释为动画集数。
- 不把网站不支持的进度写入短评、标签等其他字段来模拟进度。
- 不支持的具体指标应明确解释，不能报告为更新成功。

### 3.2 已核实的源码能力映射

详细证据见 [进度能力调研](progress-capabilities.md)。已完成服务端和 CLI 源码核实、五类公开搜索/详情、五类真实账户收藏读取，以及动画/三次元个人章节、书籍进度字段读取；没有进行真实账户写入验证。

| 媒体类型 | 当前 p1 原生进度方式 |
| --- | --- |
| 动画 | 服务端允许单集状态更新；累计标记由完整主线章节清单编排 |
| 书籍 | 服务端允许章数、卷数独立更新 |
| 三次元 | 服务端允许单集状态更新，需存在对应章节 |
| 音乐 | 服务端拒绝细粒度进度写入；使用收藏状态表达进行或完成 |
| 游戏 | 同音乐；首版不添加路线、时长或百分比等本地记录 |

bgm-cli 提供书籍章数、卷数及独立单集更新路径，但 CLI 存在命令不等于服务端允许该媒体类型。M4 已接入上述原生写入和回读验证，离线验收通过；特定账户的线上写入尚未验证。

### 3.3 已确认的业务语义

- “看到第 N 集”：累计标记主线第 1～N 集。
- “第 N 集看过”：仅修改指定主线单集。
- SP、OP、ED 等特殊章节需明确指定。
- 父条目未收藏时，提示用户选择收藏状态。
- 到达最后一集时提示是否修改收藏状态，已有收藏不自动联动。

### 3.4 已确认的边界及实现限制

- 用户在 M4 确认：明确退回第N集只移除其后的主线已看状态，不补齐前面的未看章节，保留特殊章节及其他状态；清空移除全部章节状态或书籍两个计数归零。两者先预览确认。超过已知集数拒绝写入；累计范围缺失或重复整数主线编号时拒绝累计操作。
- 书籍章数与卷数独立更新；总数已知时拒绝超限，总数未知时不推测。单个计数回退/清零亦先确认。
- 累计更新只生成目标章节，不默认清除后续已看记录；涉及回退或清空时再按相应权限处理。
- 更新清单必须基于完整章节列表；已实现每页20项的偏移分页及完整清单汇总（最多100页/2000项）。仅 `complete: true` 表示持有完整清单，缺页、重复、总数变化及中途失败均拒绝生成完整结果。

- 模型配置包含接口、模型名、环境变量引用及思考开关；可通过 `--model` 选择配置。
- 会话采用追加 JSONL，只从已完成轮次恢复历史，不重放工具；当前不做自动上下文压缩。
- 当前尚未实现查询缓存和长期偏好。
- CLI 与配置说明见 [README](../README.md)，示例见 [配置文件](../config/examples/config.json)。
- `doctor` 只检查本地配置及 OAuth 环境变量是否存在；`auth-check` 在线只读核实当前账户，仅返回 ID 与用户名；Token到期前可刷新认证，不修改收藏或进度。
- 用户已选择 OAuth 主登录：默认浏览器访问 bgm.tv/oauth/authorize；固定 `127.0.0.1` HTTP 回调验证随机state及单次code，立即POST bgm.tv/oauth/access_token交换Token，通过p1/me核实同一数字账户后原子DPAPI保存。默认回调 `http://127.0.0.1:43835/oauth/callback`、等待3分钟；clientId/clientSecret仅以环境变量引用配置，用户自行登记应用，失败或保存前取消保留原认证。
- 查询/写入桥接使用相同 OAuth Bearer，固定next.bgm.tv/p1路径，不混用旧p1会话、Cookie或其他应用Token，不修改node_modules。旧Cookie密文保留但不读取。公开请求不依赖到期认证；个人请求到期前刷新、核实同账户并防止覆盖并发退出/重新登录，不自动重发业务写入。
- login-status仅返回本机元数据及到期状态；logout仅清除本机OAuth，不承诺注销网站其他会话。OAuth登录不依赖Playwright或专用窗口；当前真实应用授权与Bearer的账户线上兼容未验收。
- 条目取消收藏暂不开放：模型工具/提案、旧CLI、宿主计划和实际执行桥接全部拒绝，不读取网页Cookie、不提交删除；不会用状态0、搁置或抛弃模拟。此前方案为历史研究，后续获取方式另行讨论。
- 上游收藏查找回退范围为前100项；失败保持“未读取到”而非推断未收藏。章节超过汇总上限时支持继续分页查询。
- M3 已落实宿主候选选择与操作授权绑定；M4 已组装实际写入器。查询事实从已完成轮次恢复；旧预览授权不恢复，操作记录独立于对话日志。取消后独立回读核查，不自动重试。

## 5. 操作权限

### 5.1 已确认原则

采用权限方案 B：

> 用户明确要求的单项修改直接执行；复杂操作先展示具体变更，再确认。

建立明确的操作权限规则表，由代码统一判断；模型不能自行授予操作权限。

### 5.2 已确认的权限规则（2026-10-02）

用户在 M3 开发中明确选择采用下表规则。权限分类已由确定性代码实现；M4 已连接确定性授权和实际写入器；线上持久化验收单列，尚未进行真实账户写入测试。

| 操作类别 | 已确认规则 | 执行条件 |
| --- | --- | --- |
| 查询、推荐、统计、生成收藏短评草稿 | 直接执行 | 不附带网站写入 |
| 单项收藏状态、评分、标签更新 | 直接执行 | 用户明确要求，目标与修改值确定 |
| 单个作品进度更新 | 直接执行 | 更新语义明确；同一作品连续多集可视为一次进度操作 |
| 收藏短评更新 | 最终正文已授权时执行 | 用户提供最终正文，或选定草稿并明确要求保存 |
| 多作品批量修改 | 预览后确认 | 展示完整对象清单和各项改动 |
| 条目取消收藏 | 暂不开放 | CLI、工具、宿主计划和执行桥接均拒绝，用户到网站操作 |
| 清空进度 | 预览后确认 | 展示将移除的章节状态或书籍计数及影响；不等同于条目取消收藏 |
| 降低进度 | 预览后确认 | 展示具体回退对象和范围；累计新增仍不默认清除后续已看章节 |
| 修改公开或私密设置 | 预览后确认 | 展示可见性变化 |
| 未指定字段的附带影响 | 预览后确认 | 单列额外变化；例如 bgm-cli 将想看状态的评分设为0 |
| 登录、凭据配置、账户切换 | 用户专用交互 | 凭据不经过模型，切换时展示目标账户 |
| Agent 自行提出的修改 | 等待用户授权 | 推荐和分析结果本身不构成写入授权 |

收藏短评作为个人收藏字段讨论；首版不提供社区发帖、评论区回复或动态发布工具。

### 5.3 已落实的授权与消歧机制

- 目标不唯一时先选择，这是消除歧义，不是重复权限确认。
- 授权绑定具体对象和改动；清单或正文变化后，原确认不自动覆盖新内容。
- 展示未授权的附带影响，例如改为“想看”可能清除已有评分。
- 对已经明确确认的具体操作不重复确认。
- 外部条目介绍、评论或其他数据不能授予操作权限。

- 宿主给搜索结果分配固定候选清单和编号，日常不要求输入清单ID。唯一结果自动成为当前对象；多个结果需用户编号、完整名称或明确ID/链接选择，同名则继续消歧。“这个”“它”绑定唯一结果或已明确选中的焦点，模型不能从多个结果中猜写入对象。
- 收藏预览支持状态、评分、标签、最终短评和可见性，可按完整对象清单批量预览。先读取账户与每个条目的现有收藏，再计算字段变化及附带影响；读不到现状时不推断未收藏，不生成完整预览。
- 常见自然语句由完整句式规则解析对象、字段和最终值，包括“这个结果是对的，把他改成8分”；复杂表述通过现有模型循环的 `propose_dialogue_request` 解析，原文及指代需逐字来自真实输入、参数需领域校验，模型提案始终先具体预览确认。否定、假设、问句和外部文本不能直接授权；Schema合法不等于用户授权。
- 当前进程保存未完成请求、缺失对象/分值/收藏状态及原始用户消息；用户只回复“第一项”“八分”“看过”可补齐原请求，不要求重复。新任务或取消清除旧请求。缺状态的评分请求补全后保留评分并明确创建；进度请求先授权创建收藏，成功后重新读取并展示进度预览，不自动联动。
- 自然语言确认/拒绝及 `/confirm`、`/reject` 都在进入新模型轮次、使旧预览失效之前由宿主消费，不注册为模型工具。确认只能针对本次终端实际展示的最新有效预览，绑定账户、对象、参数和全部附带影响。确认同时修改参数则失效旧计划、重新规划；一次明确请求最多生成一次直接授权。执行前核对账户和现状，补全期间换账户或现状变化停止。
- 恢复会话只恢复完成对话及候选选择事实，不恢复未完成修改请求、预览或旧授权；新普通对话、候选选择或重建预览仍使旧预览失效。确认范围不符、重复确认或没有有效展示时不执行。
- `ask/chat` 实际执行明确授权的单项；复杂项由宿主确认。独立 `preview` 仍只预览。结果提供逐作品及字段/章节状态，只有回读匹配才能返回成功；取消/超时后在独立30秒读取窗口内最多核查三轮，不重新发送写请求。
- 当前 bgm-cli 缺少完整结构化收藏字段、书籍清零及可靠未收藏识别入口，M4 用固定子进程桥接锁定的 bgm-cli 客户端；本人收藏分页最多10000项，缺页、重复、总数变化均拒绝创建推断。执行前绑定完整字段与章节，实际单集写入前再次核对所属作品和原状态；仍不保证跨进程或网站并发编辑的原子一致性。
- 未收藏时仅在用户选择状态后创建，未指定字段使用网站默认值（评分0、空标签/短评、公开、进度0）；进度请求不隐式创建，收藏完成状态不自动完成进度。最终短评规范化为NFC且最多380字，标签不含空白，保留逗号内容。
- 条目收藏删除已按用户选择重新接入统一网页登录；官方 v0/p1 和锁定 bgm-cli 没有相应删除入口，不用其他状态模拟删除。预览读取完整收藏及关联章节，核实网页目标入口；所有删除均待宿主确认，提交前重核基线及账户，使用当次动态 gh，单次提交后独立回读。章节保留/改变/未知单列，核查失败保留整体未知，不额外清空或自动恢复；详见[删除能力说明](collection-delete-capabilities.md)。
- 降低、清空、超限语义已在本轮由用户确认并落实，范围见3.4；实际账户权限、回读延迟和上游部署表现待联调。

## 6. 可靠性与验收建议

### 6.1 可靠性要求建议

- 修改前读取相关现状，保留未要求修改的字段。
- 网站写入后回读验证，区分成功、失败和结果尚不确定。
- 网络超时后先检查状态，再决定是否重试。
- 会话恢复不自动重放已执行的写操作。
- 支持用户取消任务，明确报告已完成和尚未开始的操作。
- 批量任务报告逐项结果；独立项失败与依赖步骤失败分别处理。

### 6.1.1 未登录与网络故障回退（2026-10-02）

- 用户要求需要登录的用户命令在未登录时返回登录引导，明确本助手需登录 Bangumi 才可提供相关账户功能，不继续无意义的重试。
- 本次公开搜索故障已核对为 `BGM_NETWORK`：当前应用默认直连超时，同路径匿名请求及实际查询桥接指定 Clash 7890 后成功。公开搜索不应被统一锁在登录后，也不能把网络失败当成登录失效。
- 具体工程方案见[诊断与回退建议](auth-network-fallback-proposal.md)：共享认证守卫、错误分流、宿主结束本轮重试、现有 `/login` 引导及非交互命令提示。用户要求的方向已明确，方案尚未实施；登录后不自动重放修改，已发送写入仍先独立回读。

### 6.2 后续需要落实的验收场景

- 五种媒体类型的搜索、详情和收藏操作。
- 各类型原生进度，以及没有对应进度指标时的明确提示。
- 多轮候选指代、同名作品消歧和关联作品识别。
- 明确单项直接执行、批量预览、拒绝确认和附带影响提示。
- 评分、标签或状态更新不覆盖其他收藏字段。
- 写入验证延迟、请求超时、取消和会话恢复。
- DeepSeek 流式输出、工具调用、错误返回和凭据脱敏。
- 基于个人记录的动画推荐，过滤已看作品并给出依据。
