# 联调与发布建议草案

- 日期：2026-10-02
- 状态：建议，待用户讨论后修订；不构成真实账户写入、发布或新增功能授权。
- 基础：M4 收藏/进度、自然语言扩展、网页登录统一认证及网页删除开发完成；离线测试结果见[开发规划](development-roadmap.md)，真实登录兼容及写入未验证；M5 暂缓。

## 1. 建议的交付范围

先交付“查询 + 收藏 + 原生进度”的本地 CLI 试用版；推荐暂不作为验收门槛，也不宣传已提供个性化推荐。M6 分为线上验收与本地交付两个步骤。

当前没有 Git 仓库，建议开始联调前建立本地 Git 基线，方便记录修复及版本回退；是否同步远端、是否公开由用户另行决定。当前 `package.json` 为 private，不直接发布 npm。先用私有源码包/压缩包自用，在线验收通过后再讨论公开仓库或 npm 分发；首轮无需制作安装器或 Windows exe。

## 2. 联调顺序与通过条件

| 顺序 | 场景与检查 | 通过条件与边界 |
| --- | --- | --- |
| 1 本地与认证 | 类型检查、构建、离线测试、帮助、doctor/login-status；用户在 login 专用官方网页完成登录，实际 auth-check | 不读取日常浏览器或旧 bgm-cli 凭据；DPAPI保存，Cookie/UA的网页与p1账户一致；验证码由用户完成；本机状态与在线认证区分 |
| 2 真实只读与模型 | 五类搜索/详情/收藏；DeepSeek 普通与思考配置；search→选择→详情；恢复指代 | 模型使用实际工具，ID/媒体匹配；其他模型不默认宣称通过；只读场景避免带修改意图 |
| 3 单项收藏 | 在明确测试条目修改状态、评分、标签、最终短评；想看清评分、私密变化单独确认 | 修改前保存本地快照；用户指定对象、最终值和恢复范围；回读所有应保留字段并在网站人工抽查 |
| 4 原生进度 | 动画/三次元累计、单集、明确SP；书籍章数/卷数；音乐/游戏拒绝细粒度写入 | 累计不清后续；到末集不改收藏；不支持请求无写入。不要拿真实长期观看记录随意做破坏性测试 |
| 5 复杂与恢复 | 在授权测试条目做回退、清空、多作品确认/拒绝；旧预览、账户/现状变化；退出/恢复 | 拒绝不写，旧授权不恢复，逐项记录真实结果。断网、超时和取消优先模拟；若线上测试，单独明确对象和故障注入范围，未知结果先人工核对 |
| 6 干净环境安装 | 独立临时用户目录，从交付源码运行 npm ci、build、doctor、help；再由用户配置认证 | 使用锁文件；不复制真实配置、会话或 node_modules；README 可独立照做。安装验证不要求真实写入 |

建议真实写入测试首先选1个动画/三次元条目、1个书籍条目和1个收藏字段测试条目，避免批量污染账户。创建新收藏单列授权：默认公开；网页删除已接入但线上未验证，删除对象与关联章节影响单列授权，不能把“建完立即删除”作为自动清理承诺；优先使用已有收藏。每组测试列出具体ID、操作、期望、未要求字段和是否恢复。恢复本身也是实际修改，需覆盖在用户批准的操作清单中；发生未知结果时先核查，不能自动恢复造成二次写入。

证据保存到独立用户数据目录，输出脱敏结果摘要；不把完整收藏、个人短评或真实配置加入源码。在线失败首先归因到适配器、账号权限、模型行为或上游限制，不把离线通过当作线上通过。

## 3. 发布门槛与回退

- 联调清单逐项记录“通过/失败/未测”及对象范围；真实写入回读和必要人工抽查通过后，才将 M4 在线验收标为完成。
- 建议先标记为本地试用版本，确认版本号与本轮交付内容；不把 M5 当作版本必需项。
- 在干净目录验证安装和锁文件；检查压缩包仅含必要源码、文档、示例、锁文件及构建说明，排除凭据、真实用户配置、缓存、会话、日志、测试临时数据。
- 公开前确定本项目许可证与 bgm-cli 的 AGPL-3.0-only 依赖声明处理；保留上游来源与许可文件，不先发布再补。
- 应用回退采用上一个代码版本，保持用户数据目录独立；程序回退不会撤销已发生的网站修改。未知操作记录保留供人工核查，不删除记录或重放写入。

已知限制应随交付说明：统一网页登录凭据保护当前仅支持 Windows，需本机 Edge/Chrome；真实网页登录及传统 Cookie/UA 的 p1 兼容未验证，网页删除控件及章节级联依赖网站部署；长章节核查可能较慢；完整本人收藏查询最多10000项，章节最多2000项；无自动上下文压缩和并发写入保障；旧 bgm-cli 密码输入现象为历史问题；线上服务部署和账号权限可能与源码不同。
