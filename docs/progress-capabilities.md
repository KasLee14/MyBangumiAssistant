# Bangumi 原生进度能力调研

- 调研日期：2026-10-02
- bgm-cli：npm `1.1.2`；参考源码快照 `798b2150f3256e433c8ca3a3432276aefc6461bc`
- server-private：源码快照 `fb86d54368bffe3dca79054dc24b32a35b1b1eef`
- 验证边界：源码调研、五类公开搜索与详情、五类账户收藏只读、动画/三次元完整章节与个人状态、书籍进度字段读取；没有账户进度写入验证。

## 1. 结论

当前 p1 服务端并未对所有媒体类型提供细粒度进度写入。Agent 覆盖全部类型的查询与收藏能力，但不能把不支持的写入报告为成功；不建立本地补充进度。

| 类型 | 原生细粒度能力 | bgm-cli 入口 | 证据与限制 |
| --- | --- | --- | --- |
| 动画 | 单集状态；主线累计可由多单集操作编排 | `episode list`、`episode status`、`episode watch` | 单集更新服务端允许；父条目需先收藏；watch 按主线编号匹配 |
| 三次元 | 与动画相同的单集状态 | 同上 | 单集更新服务端允许；具体条目必须存在对应章节 |
| 书籍 | 章数、卷数 | `book get`、`book ep`、`book vol` | 不走动画式单集状态更新；章数和卷数独立 |
| 音乐 | 当前 p1 不支持细粒度写入 | 可读取条目及章节；收藏状态独立管理 | 单集和条目计数进度端点均拒绝该类型；存在曲目不代表可标记进度 |
| 游戏 | 当前 p1 不支持细粒度写入 | 可读取条目；收藏状态独立管理 | 同上；游玩时长、路线和百分比均不属于首版能力 |

音乐和游戏仍可以修改“想看/想玩/想听、进行、完成、搁置、抛弃”等底层收藏状态；M4 已接入这些写操作与回读验证，真实账户写入尚未验证。

## 2. 接口证据

- [服务端收藏与进度路由](https://github.com/bangumi/server-private/blob/fb86d54368bffe3dca79054dc24b32a35b1b1eef/routes/private/routes/collection.ts)：`PATCH /collections/episodes/:episodeID` 只允许 Anime、Real，其他类型抛出 `subject not supported for progress`；要求父条目收藏。
- 同一路由的 `PATCH /collections/subjects/:subjectID` 接受 Anime、Real、Book，拒绝其他类型。动画/三次元的计数更新会重建主线已看集合，可能清除后续已看状态，不能无条件替代累计新增。
- [请求定义](https://github.com/bangumi/server-private/blob/fb86d54368bffe3dca79054dc24b32a35b1b1eef/lib/types/req.ts)：章节写入支持 `type`、`batch`；批量路径与普通单集路径不同。
- [首页进度管理器](https://github.com/bangumi/server-private/blob/fb86d54368bffe3dca79054dc24b32a35b1b1eef/lib/home/progress.ts)：管理范围为 Anime、Book、Real。
- [bgm-cli 单集命令](https://github.com/aronnaxlin/bgm-cli/blob/798b2150f3256e433c8ca3a3432276aefc6461bc/src/commands/episode.js)：`episode watch` 只修改一个主线章节，不自动更新前面全部章节。
- [bgm-cli 书籍命令](https://github.com/aronnaxlin/bgm-cli/blob/798b2150f3256e433c8ca3a3432276aefc6461bc/src/commands/book.js)：分别调用章数、卷数更新并回读验证。

以上是源码事实，线上部署可能滞后或变化。实现写入时仍需要对特定账户和条目进行单独验证。

## 3. 用户已确认的语义

- “看到第 N 集”：累计标记主线 1～N 集。
- “第 N 集看过”：仅修改指定主线单集。
- 特殊章节需明确指定，不从主线编号自动猜测。
- 未收藏条目：提示用户选择收藏状态，然后才考虑进度操作。
- 到达最后一集：提示是否修改收藏状态，已有收藏不自动联动。

M4 已在完整个人章节清单上生成逐项变更并实际执行。累计选择不会清除后续已看；用户确认的回退仅移除后续主线已看，保留特殊章节及其他状态。清空移除所有章节状态或清零书籍两个计数；回退/清空须确认。已知总数超限拒绝写入，不添加本地指标。

## 5. M4 写入适配与验证边界（2026-10-02）

- 固定子进程桥接 bgm-cli 1.1.2 的 `upsertMyCollection`、`patchMyCollection`、`updateMyEpisodeCollection`，不暴露任意请求或 shell；收藏显式 `progress: false`，单集显式 `batch: false`。
- 收藏字段整体保留；书籍两个计数可独立写入及归零。个人章节未知状态通过已认证的单章详情补充，不能仅凭缺失的列表字段推断未看。
- 本人收藏完整分页最多100页/10000项，只有条目可读且完整分页未命中才返回未收藏；独立只读 CLI 的旧100项回退限制仍存在。
- 参考[当前调研快照的收藏路由](https://github.com/bangumi/server-private/blob/fb86d54368bffe3dca79054dc24b32a35b1b1eef/routes/private/routes/collection.ts)及[请求定义](https://github.com/bangumi/server-private/blob/fb86d54368bffe3dca79054dc24b32a35b1b1eef/lib/types/req.ts)，本轮核实 p1 没有条目收藏删除路由，不能提交 type=0 模拟删除；不代表已核实所有其他协议。最终短评限制380字（NFC），标签不能包含空格；本地按空白字符收紧校验。
- 61项离线测试（包含16项M4集成测试）通过：五类收藏保留、原生进度、回退/清空、拒绝/确认、超时取消后核查、部分成功、现状与账户变化、实际桥接假依赖和CLI假子进程。
- 没有执行真实账户写入，不把子进程返回成功或Mock回读当作线上持久化证明；线上验收范围待联调方案确定。

### 统一网页登录后的验证边界（2026-10-02）

- 用户已选择网页登录统一认证；读写桥接复用锁定 bgm-cli 客户端的数据转换，认证改为同一传统 Cookie 与 User-Agent。原生进度语义和权限规则保持现有设计。
- 临时假凭据通过实际 Windows DPAPI 保护；真实查询/写入 worker 在假网络下完成查询、收藏更新、删除及回读，不发起网站账户请求。
- 本文 M2 在线读取证据来自旧认证，不能代替新网页登录、Cookie/UA 线上兼容或真实进度写入证明。新登录及具体账户写入仍需单列验收；删除细节见[收藏删除能力](collection-delete-capabilities.md)。
