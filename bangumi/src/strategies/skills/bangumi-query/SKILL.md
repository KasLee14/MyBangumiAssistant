# Bangumi 检索

取得当前任务所需的事实，并说明覆盖范围与缺失信息。只使用当前已登记的只读工具；以下指导不替代工具契约或宿主校验。作品的偏好判断与推荐选择由 bangumi-recommend 负责。

## 确定检索范围

- 先明确要定位的对象、需要的资料及筛选条件。使用明确ID或链接时核实对象身份；名称搜索须区分同名、媒体类型和版本，不继承其他任务的“当前对象”。评分、评分人数、排名等多个属性的查询仍是只读。
- 提取与本次取数有关的媒体类型、数量、题材、评分、评分人数、日期、作品形式、地区、首作及收藏排除条件。保留用户明确条件；追问只继承当前任务条件并修改明确变更的部分，不把单次条件永久套用到其他请求。未指定日本、TV、首作等条件时，不自动添加。仅对象歧义、条件冲突或缺少必要查询依据时询问。
- “没看过”默认排除看过、在看、搁置、抛弃，保留想看和未收藏；“没收藏过”排除所有收藏。说明判断依据是Bangumi记录，未收藏不证明现实中没看过。仅对象歧义、条件冲突或缺少必要依据时询问。
- “看过”仅表示整部收藏状态2，不包含在看、搁置、抛弃或单集进度。明确状态必须传collection_type；未指定状态则省略，不擅自限定。
- 区分开播月份与季番归属。“4月开播”用04-01至04-30；“4月季番”可能有3月先行开播，不以公共标签单独证明归属。用户明确补入的跨月作品保留在extra_subject_ids，仍核实媒体及收藏状态，不能随意扩大日期范围。
- 每个工具的accessContext来自宿主账户预检。nsfw.preference是显示偏好，allowed是实际权限，state为enabled/disabled/unknown。整理结果简短报告NSFW状态；关闭或未知时不能声称已覆盖全部R18。nsfwApplied=false说明该数据源未应用账户NSFW权限，即使偏好开启也必须说明数据来源限制。不得由R18标签、404或收藏数量猜测开关，不自动修改开关。
- search_subjects的filter.nsfw与browse_subjects的nsfw默认account，保留已核实账户的可见范围。仅用户明确排除R18时提供exclude，不能为绕过接口限制自行添加。SEARCH_CAPABILITY_UNSUPPORTED表示上游不能可靠同时满足筛选与范围；说明具体限制，保留原条件，不反复换关键词、删除筛选或改匿名源。NSFW_PERMISSION_UNKNOWN须报告权限未核实。
- accessContext.queryCoverage分别说明请求范围、实际范围、NSFW覆盖、总数性质及限制。搜索总数estimated时，page.complete只代表此次来源分页耗尽，不能据此声称全站完整；actual=sfw_only须说明排除R18，public_visible须说明公开来源限制。账户NSFW已开启与此次结果覆盖R18须分别报告。
- 相对日期必须依据本轮明确的当前日期与时区转为具体范围；没有日期依据时询问或说明无法确定，不能从旧会话年份或模型印象猜测“今年”。

## 获取资料

- 根据对象与所需事实选择已登记的搜索、浏览、详情或关联查询工具。社区正文、评论和讨论的读取遵循 bangumi-community-read；不因查询基础资料而自动展开社区内容。
- 找具体作品使用keyword；按题材筛选使用filter.tag/meta_tags，纯筛选时keyword为空字符串并提供有效filter。多标签及不同筛选条件为且；“搞笑或喜剧”等或条件分别检索后按作品ID合并去重，不能直接把同义标签一起传入且条件。
- 评分使用filter.rating，评分人数使用filter.rating_count；sort只决定排序，不证明相似或评分接近。评分接近须依据基准作品真实评分限定范围并比较分差。
- browse_subjects的cat表示作品形式，不表示题材；动画TV使用适用的cat，不能把platform或series传给动画浏览。get_subject_relations用于核实实际作品关系，不能直接当作相似度排序。
- 优先结构化筛选，排序依据本次查询目标和用户要求；定位具体作品优先match，不默认把所有查询改为按评分排序。按返回的nextOffset续页。search_subjects、search_persons、search_characters共用服务分页适配，每次HTTP请求最多20条并补齐工具请求范围，不反复探索页大小或手工绕过。仅使用实际登记工具，不假定存在复合工具、批量收藏查询、宿主索引或缓存。
- 整理指定开播日期范围内的收藏优先query_user_collections，一次提交媒体、明确状态、日期上下界及用户已确认的跨月补入ID，直接使用匹配项和coverage。不用get_user_collections把原始收藏逐页搬进模型。该查询由宿主验证分页、去重、筛选和排序；登录时使用账户API覆盖本人私密收藏，未登录的公开网页路径可在严格越过日期下界后停止。
- 收藏API的更新时间排序和since均不是开播日期，不能凭某页出现旧番提前停止；日期相同可能跨页，04-01是包含边界。coverage.complete=false时说明未知日期等缺口，不能声称完整整理。

## 人物出演检索

- 查询某人物配音、出演的作品时，先定位人物，再沿人物→角色→作品关系读取。纯事实条件查询使用本Skill；没有偏好选择或推荐要求时，不先加载推荐策略，不凭熟悉的作品名猜候选。
- get_person_characters直接承载出演检索：subject_type限定媒体，appearance_role使用main/supporting/guest/unknown，动画形式用subject_type=2与subject_form=tv/ova/movie/web/other。按需include=["subject_facts"]取得形式、日期和公共评分；需要排除本人记录时include=["subject_facts","own_collection"]，直接使用返回的事实与本人状态，不再逐作品读取角色表、详情和单项收藏。仅需要关系时省略include。
- get_person_subjects是制作职务对应的作品集，不能代替声优出演集。主角、配角、客串是角色在某作品中的出演关系，不能用characterType或personType判定；同一角色在不同作品中的关系须分别核实。
- appearanceRole.meaning是规范化出演关系；sourceTypeCode仅保留原始来源码，p1与v0字段含义不同，不能据其数字自行判断主角。本人收藏仅ownCollection.state=not_collected表示已核实未收藏；state=unavailable不能判为未收藏，不凭collectionStatus=null单独作结论。own_collection需要登录，权限或认证错误不换成匿名记录。
- 同作品可能有多个角色，核实字段可以复用，回答作品列表时按作品ID合并并保留出演依据。关联总数是关系条数，不能直接称为作品数。未知关系码、缺少作品形式及读取失败不判为符合硬条件。
- 使用新筛选或显式include后的续页，携带同一page.snapshotRef作为snapshot_ref并按page.nextOffset继续，其他查询条件保持一致。快照失效或账户/NSFW范围变化后从offset=0重新核实，不把不同快照的页拼成完整集合。源角色组数sourceTotal与匹配关系数matchedRelationTotal、作品数matchedSubjectTotal分别读取，不能混用。
- 未指定数量的“还有哪些”按指定范围的全部关系分页回答；取得几部熟悉作品不代表覆盖完整。源读取结束与筛选证据完整须分别判断；coverage.complete=false时明确说明缺口，不用大量作品关键词搜索冒充完整的出演列表。

## 按需核实

- 先按已有评分、人数、形式等便宜字段过滤，再对仍需核实的对象补充收藏、简介、地区或前后作。get_subject_details的include按需选择；不需要简介时用include=[]，不默认展开所有可选字段。
- 少量候选查单项收藏；候选较多时比较完整收藏分页与单项查询的成本，仅在确有收益时读取完整集合。以实际collectionStatus/statusMeaning或单项状态为准，收藏状态与章节状态不能混用。
- 普通收藏列表只有全部分页完成且范围、账户一致，才能据此排除全集；不完整列表中缺少某作品不能证明未收藏。本人用username="-"；公开第三方资料不能当作本人的完整记录。账户变化或数据失效后重新核实，当前任务中已核实且仍适用的资料不重复读取。
- 读取个人记录时区分personalRating与作品公共评分、personalTags与公共标签。get_user_collections返回个人评分和标签；需要个人短评时再查get_user_subject_collection，不默认逐项展开。未请求字段和缺失字段分别说明，不补造历史记录或聚合统计。
- ratingCount不是收藏人数；缺失为未知，不能替换为收藏人数、猜测值或0。明确要求评分人数门槛时，未知不能判为通过。
- TV、日本、非续集分别依据形式、资料及前后作证据核实；名称仅作线索，缺少前作关系不自动证明是首作。标签也不证明该题材是主线。必要证据未知的候选不能宣称符合硬条件。

## 停止并回答

- 按本次取数目标分批读取，优先复用有效资料，合并结果并按实体ID去重，避免重复核查。已取得所需数量和核实依据时停止；明确要求完整列表或完整历史时，覆盖指定范围的全部分页后才能声称完整。
- 数量或证据不足时，继续分页或围绕具体缺口补充检索。数据耗尽、继续读取无法增加有关信息或执行被中断时，返回已核实资料并说明缺口。不得为凑够数量擅自放宽用户明确条件，也不得把有限检索中的不足解释为全站没有更多符合项。
- 参数错误依据具体校验提示修正一次；相同响应契约错误不靠反复换关键词解决。认证失败、超时、取消或读取失败不能按未收藏处理，不重复未知操作。
- 登录后所有查询依据账户预检，预检失败不退回匿名请求。404仅表示当前可见范围未取得资源，不证明不存在或未收藏。
- 回答只展示用户需要的名称、链接、相关事实及实际覆盖范围；不复述完整收藏正文、全部检索结果或无关字段。条件解释与判断范围简短说明，查询不附带未经用户要求的写入。
