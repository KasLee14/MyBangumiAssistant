# Bangumi 检索

检索使用“召回 → 筛选 → 字段补全”的漏斗。宿主保存接口已经返回的完整资料，模型只接收所选字段和进度；需要更多资料时沿候选引用读取，已有字段复用缓存，缺失字段由宿主读取相应资源后补全。作品的适配判断与推荐选择由 [bangumi-recommend](../bangumi-recommend/SKILL.md) 介绍。

## 候选与资料

搜索、浏览、收藏或人物出演可用 `result_mode="candidates"` 取得候选引用。召回工具选择适合用户目标的来源条件，`fields` 选择当前需要查看的资料。作品关系扩展是独立召回操作，适合用户需要沿前作、续作等关系查找的任务。

`refine_subject_candidates` 沿 `candidate_ref` 用 `filter` 执行事实条件，用 `fields` 读取必要字段。宿主补齐筛选依赖，无需同时将它们全部展示给模型。评分、日期、形式、收藏状态属于事实；类别、题材主线和体验相似性由模型根据资料判断。标签是语义线索，精确标签命中范围不等于通俗类别的全部作品。模型选定成员后，可用 `filter.subject_ids` 从已有引用取得最终集合。

`candidateRef` 是当前工作集，`resultRef` 是累计通过的结果集；当前页 `data` 只是窗口。需要继续处理时使用返回的游标与 `continue_subject_query`，需要下一页来源时使用来源工具的分页参数。中间结果仅需引用和进度时，可使用 `response_view="reference"`；需要阅读资料时使用 `page`。参数、枚举和窗口限制以工具契约为准。

收藏证据通过 `collection_ref` 复用。本人收藏使用 `username="-"`。只有完整且适用的账户、媒体和状态范围，才能以缺席证明未收藏；局部样本中没出现仍是未知。

## 范围与交付

未知或读取失败不等于不符合。根据用户需要选择少量结果或继续取得指定范围；全量结果需要来源和候选处理均已结束，并说明仍缺失的必要证据。完成信息只针对实际读取范围，搜索估计总数、公开或 SFW 来源不能证明全站、私密或 R18 范围完整。

交付名称、链接及用户需要的资料，并区分事实与语义判断。可沿最终引用调用 `prepare_candidate_output` 生成展示内容，也可按应用输出契约直接回答。引用用于当前读取任务；跨任务重建必要来源，压缩上下文时保留引用、条件、续页位置和证据缺口。

## 简短例子

用户要找评分至少 8 分、适合轻松观看的动画：先搜索或浏览动画候选，取名称与评分；沿引用以 `filter.rating.min=8` 筛选，再按 `fields` 读取标签、简介判断风格。需要更多合格候选就继续来源分页，资料不足就沿原引用补字段，选定后用 `filter.subject_ids` 取得最终成员。评分筛选由宿主执行，“轻松”由模型依据本次资料判断。
