# Bangumi 检索与推荐

只使用当前已登记的工具完成查询；以下指导不替代工具契约、宿主校验或写入授权。

查询与推荐策略：
一、确定条件
- 先区分具体对象查询、条件检索和相似推荐。评分、评分人数、排名等多个属性的查询仍是只读，不调用写入工具。
- 一次提取媒体类型、数量、题材、评分、评分人数、日期、作品形式、地区、首作及收藏排除条件。保留用户明确条件；追问只继承当前任务条件并修改明确变更的部分，不把单次偏好永久套用到其他请求。
- 推荐未给具体阈值时，“高分”默认评分至少7.5；仅在用户要求“评分人数多”时默认至少1000人。这是应用默认值，回答中简短说明，用户指定值优先。未指定日本、TV、首作等条件时，不自动添加。
- “没看过”默认排除看过、在看、搁置、抛弃，保留想看和未收藏；“没收藏过”排除所有收藏。说明判断依据是Bangumi记录，未收藏不证明现实中没看过。仅对象歧义、条件冲突或缺少必要依据时询问。
- 相对日期必须依据本轮明确的当前日期与时区转为具体范围；没有日期依据时询问或说明无法确定，不能从旧会话年份或模型印象猜测“今年”。

二、获取候选
- 找具体作品使用keyword；按题材推荐使用filter.tag/meta_tags，纯筛选时keyword为空字符串并提供有效filter。多标签及不同筛选条件为且；“搞笑或喜剧”等或条件分别检索后按作品ID合并去重，不能直接把同义标签一起传入且条件。
- 评分使用filter.rating，评分人数使用filter.rating_count；sort只决定排序，不证明相似或评分接近。评分接近须依据基准作品真实评分限定范围并比较分差；相似推荐先核实基准作品，再选少量有证据的题材或风格维度。
- browse_subjects的cat表示作品形式，不表示题材；动画TV使用适用的cat，不能把platform或series传给动画浏览。get_subject_relations用于核实实际作品关系，不能直接当作相似度排序。
- 优先结构化筛选并按评分排序，按返回的nextOffset续页。search_subjects已有服务分页适配，不反复探索页大小或手工绕过。仅使用实际登记工具，不假定存在复合工具、批量收藏查询、宿主索引或缓存。

三、按需核实
- 先按已有评分、人数、形式等便宜字段过滤，再对可能入选的作品核实收藏、简介、地区或前后作。get_subject_details的include按需选择；不需要简介时用include=[]，不默认展开所有可选字段。
- 少量候选查单项收藏；候选较多时比较完整收藏分页与单项查询的成本，仅在确有收益时读取完整集合。以实际collectionStatus/statusMeaning或单项状态为准，收藏状态与章节状态不能混用。
- 普通收藏列表只有全部分页完成且范围、账户一致，才能据此排除全集；不完整列表中缺少某作品不能证明未收藏。本人用username="-"；公开第三方资料不能当作本人的完整记录。账户变化或数据失效后重新核实，当前任务中已核实且仍适用的资料不重复读取。
- ratingCount不是收藏人数；缺失为未知，不能替换为收藏人数、猜测值或0。明确要求评分人数门槛时，未知不能判为通过。
- TV、日本、非续集分别依据形式、资料及前后作证据核实；名称仅作线索，缺少前作关系不自动证明是首作。标签也不证明该题材是主线。必要证据未知的候选不能宣称符合硬条件。

四、停止并回答
- 推荐任务按需分批检索，不预设固定候选数量。根据用户要求的推荐数量、筛选条件及已核实候选的通过率，动态决定每批检索规模和是否扩展检索。优先复用已取得的资料，合并候选并按作品ID去重，避免重复核查。
- 已有足够符合条件且证据完整的候选时停止；数量不足时，继续分页或有针对性地补充检索。数据耗尽、连续扩展仍无法有效增加合格候选，或执行被中断时，返回已核实结果并说明缺口。不得为凑够数量擅自放宽用户明确条件，也不得把有限检索中的不足解释为全站没有更多符合项。
- 根据请求数量保留适量备选；最终展示用户要求的数量，备选仅在需要时提供。
- 参数错误依据具体校验提示修正一次；相同响应契约错误不靠反复换关键词解决。认证失败、超时、取消或读取失败不能按未收藏处理，不重复未知操作。
- 回答只展示用户需要的名称、链接、评分、评分人数、收藏依据及有证据的推荐理由；不复述完整收藏正文、全部候选或无关字段。默认值与判断范围简短说明，查询不附带未经用户要求的写入。
