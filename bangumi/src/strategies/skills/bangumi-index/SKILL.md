# Bangumi 目录整理

把用户要求的完整作品范围放入一个目录计划。模型负责范围与资料依据，宿主负责整批预检、一次授权、串行写入和末尾独立回读。

## 收齐目录与作品范围

- 先确定新建还是添加到已有目录，保留用户给定的标题、简介、可见性、顺序及逐作品评语；未指定时使用工具默认值，不附带收藏状态、评分或标签修改。已有目录用真实 ID 或链接定位，同名目录或作品的歧义先解决。
- 按开播日期与个人收藏整理时，优先一次 `query_user_collections`，传本次媒体、明确收藏状态和日期上下界；本人用 `username:"-"`。“看过”是 `collection_type:2`，不能用单集进度代替。相对年月依据本轮日期和时区，不沿用旧会话年份。
- “n月季番”可能包含 n-1 月先行开播。用户明确补入的跨月作品先核实 ID，再用 `extra_subject_ids` 保留，仍须符合媒体与收藏状态；不能自行扩大月份或添加未要求的作品。
- 名称搜索区分媒体、季度与版本。复用本轮有效的身份和筛选依据，仅为缺失事实读取详情；不需要简介或信息栏时使用 `get_subject_details(include:[])`，不为每部作品重复展开可选字段。按作品 ID 去重，保留用户顺序；需新增顺序时说明排序依据。
- 检查返回的 `coverage` 和 `accessContext`。未知日期、分页不完整或明确条件无法核实会影响完整性，先处理缺口，无法补齐则说明范围并澄清是否使用已核实部分，不能静默删除候选。NSFW 的显示偏好与实际权限分别读取；关闭、未知或 `nsfwApplied:false` 时说明 R18 覆盖限制，404 不证明作品不存在。已经明确的完整写入范围保留原作品 ID，由宿主预检记录不可见作品并展示跳过原因，不在模型循环里因单个 404 中止或另拆计划。

## 一次提交完整计划

- 全部范围确定后调用一次 `execute_write_batch`，把创建及所有添加列入完整 `operations`。新目录先列 `create_index`，添加项用 `index_from` 引用该创建项在计划中的序号（从 1 开始），其 `args` 省略 `index_id`；已有目录使用核实的 `index_id`。
- 每部作品的添加项保留自己的 `subject_id`、排序和评语。合并面向用户的动作摘要，例如“创建目录并加入以下 26 部作品”，逐项明细仍包含全部作品及各自设置；摘要合并不改变实际写入范围或顺序。
- 账户检查、完整预检、最终回读由宿主在批量开始和结束统一完成；不在模型循环中另做逐项账户检查、提交前预检或提交后核查。宿主按已确认计划依次提交，不能把同一请求拆成多次计划或边执行边追加作品。
- 使用宿主的完整预览与一次确认，不在聊天中重复索取确认。提交回执仅证明请求阶段，不能据此宣布目录整理成功。

## 报告实际结果

- 只依据整批最终 `state`、`summary`、各项末尾 `verification`、`actual` 及 `stageResults` 报告已验证作品数量、目录链接、跳过原因、依赖阻塞和未知结果；保留原 `step` 编号，`failures` 包含全部失败，`failure` 仅兼容首项。`partial` 不能说成完整整理，嵌套 `submission.verification:pending` 不是最终结论。
- 条目错误由宿主跳过并继续安全独立项，创建失败的依赖项为 `blocked`；附带作品全部不可执行时，宿主抑制该附带空目录创建，并说明没有创建。未知投递由宿主隔离冲突范围，账户/权限/授权变化或取消停止整批。等待同一次批工具收尾，不自动重发或新建相同目录。用户后续要求补齐时先核实已存在的目录与关系，仅在新用户轮次为剩余范围生成新计划；原授权不续用。
