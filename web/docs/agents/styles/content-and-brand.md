# 内容条目（`content.css`）

## 使用说明

### 这份文档是什么

12 种内容条目的皮肤层规则：共享基类、超椭圆例外表、行入场路径、骨架（`pending`）形态，以及每种条款的一两句要点。

**不覆盖**：条目的组件实现与 `registry` 表（见 [../components/content.md](../components/content.md)）、载荷结构与校验（宿主侧 `bangumi/src/web/message-blocks.ts` 与 `web/src/components/content/validate.ts`）、令牌定义（见 [tokens.md](tokens.md)）。上层入口：[../readme.md](../readme.md)。

### 怎么读

| 你要做的事 | 读哪一节 |
|---|---|
| 加一种新的 `kind` | [../components/content.md](../components/content.md) 的清单，再回本文件加分区 |
| 改某个条目的皮肤 | §索引「12 种条目 → 分区」 |
| 改行 hover / 指示条 / 微标签 / 表格外壳 | §规则「共享基类：先看谁在复用」 |
| 加胶囊或圆形元素 | §规则「超椭圆例外表」——**必须一并加进那张表** |
| 改入场动效 | §索引「三条入场路径」 |

### 必须遵守的规则

1. **只用 `--bgm-*` / `--app-*` 令牌，不写任何主题分支**。界面只有浅色一套外观，本文件不写 `data-theme` / `dark` 之类的选择器，也不写死十六进制；语义色需要的浅底 / 深字用 `color-mix()` 就地算。违反后果：换令牌换不动，或长出一套永不生效的主题分支。
2. **类名统一 `content` 前缀，与 `components/content/` 的组件一一对应**。样张 `web/docs/design/` 的静态复刻用的是同一批类名——改名会让样张与实现分叉。违反后果：文档页与调试页引用的类名找不到。
3. **共享基类只定义一次，条目规则只声明差异**。新增一种「行」时把类名加进那条选择器列表，不要另写一份。违反后果：同一形态出现十几份实现，改一处漏九处。
4. **胶囊与正圆必须退出超椭圆**（见下面那张表），并且**新增胶囊元素时一并加进去**。违反后果：`superellipse` 会把半圆端压成偏方，胶囊看起来不再是胶囊。
5. **信息不藏在 hover 里**：所有关键信息（章节状态、对比前后、时间线最新一条）静态可见；hover 只做「可以读得更清楚」或「可以点」的反馈。违反后果：触屏与键盘用户拿不到信息——这是刻意规避站点自身可用性问题的既有原则。
6. **只动 `opacity` / `transform`，尊重 `prefers-reduced-motion`**。违反后果：见 [../readme.md](../readme.md) §规则第 4 条。

### 共享基类与末尾三段

| 段 | 内容 | 要点 |
|---|---|---|
| 共享基类 | 行形态（`.contentRow` / `.contentInfoRow` / `.contentTimelineRow` / `.contentSubjectRow`）、柔光填充、轨道、标签、表格外壳 | 这些形态原来在多个条目里各写一遍（行 hover 5 处、柔光填充 3 处、微标签 4 处、表格外壳 2 处），现在只定义一次。`links` 的行**不在**行形态列表里 |
| 「外观层补充」段 | 各条目 hover 的增量形状 | 与 `frame.css` 同一约定：**不是覆盖层**，同名选择器已并入上面的规则；要改已有属性就回上面改 |
| 超椭圆例外段 | 所有胶囊与正圆元素的选择器列表 | 见 §规则第 4 条 |
| `pending` 骨架段 | `.contentSkeleton` / `.contentSkeletonBar` 等 | 扫光挂在 `[aria-busy='true']` 上（**开关就是语义本身**），并有 `prefers-reduced-motion` 双开关；`min-height: 84px` 只兜住骨架→真实数据的布局抖动，不追求与真实块等高（骨架期载荷未知） |

### 三条入场路径

全站入场只有三条路径，参数取自同一批令牌，所以节奏不会分叉：

| 路径 | 实现 | 用在 |
|---|---|---|
| 组件挂载即入场 | `<Stagger>`（`common.css` 的 `.appStagger`，CSS keyframes） | 短列表（侧栏分组等） |
| 滚动容器内的行 | 本文件的 `contentRowIn` keyframes + `nth-child` 延迟（第 9 项起沿用第 8 档） | 内容条目的行列表 |
| 滚进视口才浮现 | `../utils/revealOnScroll.ts` 的共享 `IntersectionObserver` | 长页面区块 |

**全站只有 `revealOnScroll.ts` 这一个模块建观察器**，不要在每个列表里各建一个。这四条规则来自 C04 的错峰表（4 档封顶会让第 5 行起同时出现，短列表尾部一次冒出好几行，所以用 8 档）。

## 规则

### 共享基类：先看谁在复用

往共享基类的选择器列表里加类名之前，先确认它真的是**同一个形态**（内容行 + hover 淡底 + 左侧主色指示条）。反例已经有两处刻意的排除：

- `links` 的行是「无线分隔 + 整行淡底」——不是同一个形态；
- `infobox` 的行有指示条会与键列抢注意力，样张给它的反馈是淡粉痕 + 内距右移。

排除要有理由，并且写进注释；不要因为「看起来差不多」就合并。

### 为什么左指示条用 `::after`

`Timeline` 的节点占着 `::before`，所以指示条统一用 `::after`。新增带指示条的行时沿用 `::after`，避免与节点冲突。

### 与样张的关系

取值口径以 `web/docs/design/index.html` 里的样张为准，**具体值写在注释里**（形如「C11 定稿 B：内距 4px → 0」「样张 `content.html` 的胶囊 hover 描边浓度」）。改一个值之前先读那段注释——它通常记着「为什么从上一个值改成现在的」，改了再改回去会重犯同一个问题。

## 现状：已删除的形态

这几处都在注释里写明了删除理由，**不要照着旧样张复活**：

| 已删除 | 原因 |
|---|---|
| `.contentEpCell:active { transform: scale(.97) }` | 章节格是展示用的，不是按钮；给了按下反馈反而误导 |
| `.contentTimelineRow:hover::before`（hover 点亮节点） | 节点只区分「最新一条」；跟着 hover 变色会让人以为「点一下会展开这一条」 |
| `compare` 行 `ins` 的绿底补充规则 | 由「箭头 + 加粗 + 主色」接管，两处并存会让同一格底色出现两个来源 |
| 骨架「不扫光」的旧结论（A 方案） | 已被 C17 定稿 B 推翻：加一条**可关的**扫光 |

另外，`content.css` 里所有指向 `docs/ui-restyle-plan.md` 的注释**指向一个仓库根下不存在的文件**（根 `docs/` 被 gitignore）——这些引用只在本地开发环境有效，不影响规则本身。
