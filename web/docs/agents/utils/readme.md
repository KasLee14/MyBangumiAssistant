# 工具层（`web/src/utils/`）

## 简介

工具层的职责与划分规则：哪些代码属于这一层、按什么切分文件、有哪些硬约束。放**与界面无关**的东西：纯函数，以及宿主接口的唯一封装。

**不覆盖**：宿主端实现（`bangumi/src`），以及各文件的行为细节——那些在各自文档里（见 §索引 的文件表）。

上层：[AGENTS.md](../../../AGENTS.md)。

## 使用说明

- **判断"某段逻辑该不该放工具层"、或要新增工具文件之前，先读 §规则**：五条约束与划分判据都在那里；违反会直接表现为工具层与界面耦合、同一错误多处重复提示，或协议类型静默不同步。
- **只想找某个功能类别在哪个文件**：直接查 §索引 的文件表，不必通读本文。
- **新增工具文件**：照 §规则 末条「新增一个工具文件时」逐步做，做完回来更新 §索引 的文件表——只加文件、不加索引，等于没人能找到它。

## 规则

### 无组件、无 hook、无状态

所有导出都是函数、常量或类型。唯一允许的副作用是 `api.ts` 里的网络请求。

| 允许 | 不允许 |
|---|---|
| 依赖 `bangumi/src/web/protocol.ts` 的类型 | import React（这里没有任何 JSX 与 hook） |
| 纯计算、数据投影、文案拼装 | import `store/`（工具层不认识全局状态） |
| 发起 HTTP / 建立 SSE（仅 `api.ts`） | 直接改界面状态或弹提示（那是 `store/operations.ts` 的事） |

判断一个函数该不该放这里：**把它单独 `import` 到一个空白脚本里，还能跑吗？** 能，就属于工具层。

**违反后果**：工具层与界面耦合，无法独立复用与测试。

### 错误只抛出、不提示

`api.ts` 只把宿主的 `ApiErrorView.message` 包成 `Error` 抛出，不做提示、不重试、不改写文案。谁调用、谁决定怎么提示（见 [../store/actions-and-operations.md](../store/actions-and-operations.md)）。

**违反后果**：同一错误多处重复提示，或调用方无法感知失败——提示与状态更新归 `store/operations.ts`。

### 不复制协议类型

跨端类型一律从 `protocol.ts` 取；这里的类型要么是协议类型的别名，要么是纯前端的投影结构（如 `TurnGroup`）。

**违反后果**：协议改动后类型静默不同步。

### 文案集中在能共用的地方

同一句话若出现在两处界面，就抽成这里的常量或函数（`AUTH_LABEL`、`relativeTimeLabel` 是范例），避免两处漂移。

**违反后果**：两处措辞漂移。

### 不写"顺手"的通用工具

没有第二个调用方的工具函数不要提前抽出来。

**违反后果**：无谓的间接层与死代码。

### 划分依据：一个功能类别一个文件

规模悬殊是有意的：`credentialLabel.ts` 只有 9 行也单独成文件，因为它是**被两个组件共用的措辞表**；而 `api.ts` 承载全部端点。**判据是"功能类别"，不是行数。**

### 新增一个工具文件时

1. 确认它是**新的功能类别**（同类别追加进已有文件即可，例如再加一条本地命令写进 `commands.ts`）；
2. 文件顶部写清"这一层为什么存在、边界是什么"（中文注释，与既有文件风格一致）；
3. 在本文件与 [AGENTS.md](../../../AGENTS.md) 的索引里登记。
