# Bangumi 助手 Web 终端

需要浏览器界面时启动 Web 终端；它与终端版共用同一套 Pi 会话、工具与授权判定，浏览器只提交命令与展示宿主生成的文本：

```powershell
npm start -- web --port 8787
```

启动后打印一个带一次性令牌的地址，并自动用默认浏览器打开：

```text
Bangumi 助手 Web 终端：http://127.0.0.1:8787/?token=<一次性令牌>
```

浏览器用该令牌换取 HttpOnly Cookie 后地址栏回到 `http://127.0.0.1:8787/`。服务只监听回环地址并校验 `Host` 与访问凭据，用 localhost 直连但没有凭据同样返回 401；带令牌的地址等同本机访问权，不要分享。`--no-open` 只打印地址，端口被占用时向后顺延并打印实际端口。

界面能力：

- 对话与流式输出：正文按块渲染（纯文本 + 12 种内容条目），流式期逐字摊平并有收尾播放。轮次结构是「轮首过程控制行 + 过程行列表（思考行 / 工具行）+ 正文 + 轮尾操作行」；思考随轮次落条目（历史里也在），工具是结构化条目（中文标题 / 工具族 / 参数摘要 / 参数原文 / 结果内容块 / 耗时 / 读写）。折叠统一走 `hidden="until-found"`，`/details` 可强制展开整轮过程，Ctrl+F 也能命中折叠内容并自动展开。
- 斜杠命令补全：本地命令（`/help`、`/new`、`/model`、`/sessions`、`/details`、`/exit`）与 Pi 已注册的扩展命令（`/bangumi-login`、`/bangumi-login-status`、`/bangumi-logout`）合并展示。
- 模型切分两步：设置弹窗的「模型配置」行填 API Key、「模型选择」行切模型，两者不能在同一次提交里完成。只有宿主报告了可用模型（某个提供方的凭据已配置）时，「模型选择」的编辑才可点，否则置灰并提示「请先完成模型配置」。历史会话在左侧栏，可新建或在列表里恢复（`/model`、`/sessions` 分别直达模型选择弹窗与会话弹窗）。
- 思考强度：输入卡右侧常驻一枚「思考 · 高」式标签，点开就地选择。可选级别与中文名全部由宿主按 Pi 的模型能力下发，浏览器不维护副本——`deepseek/deepseek-flash` 是 `off/low/high/max`，`deepseek/deepseek-v4-pro` 只有 `off/high/max`，未选择模型或当前模型不支持思考（`reasoning` 为 false）时标签置灰并说明原因。**这是界面里唯一会写本机 Pi 配置的切换**：选定后立即写进隔离目录 `pi/settings.json` 的 `defaultThinkingLevel`，重启后新会话沿用该级别（恢复旧会话时以该会话里的级别变更记录为准）；已经发出的那一轮请求参数不变。菜单向上展开，Esc 只关菜单，不会顺带停止本轮或拒绝确认。
- 写入确认：所有写入经当前宿主的 `execute_write_batch` 完整计划入口。普通单项免二次确认，发布或修改非空作品短评、全部批量类别展示中文完整范围并确认一次；全部无需修改时不提交。确认卡的标题和按钮由宿主按计划生成，提交前重新核对账户、真实输入与网站现状，写后独立回读。**没有已连接的浏览器时宿主直接拒绝写入**，不会挂起等待；连接在提交前断开则停止，已提交步骤仍独立核查，未知不重发。
- Bangumi 登录：设置弹窗「登录状态」行只显示是否登录——未登录时给出「登录」，已登录时显示已保存的用户名与「退出登录」。两者都在弹窗里完成，**不再向会话发送 `/bangumi-login`、`/bangumi-logout`**：登录弹窗一次填邮箱与密码，提交后弹窗保持打开显示宿主下发的进度（人机验证在系统默认浏览器完成），成功后自动关闭、失败则留在弹窗内可改密码重试，关掉弹窗即中止这次登录；「退出登录」先给出确认弹窗，确认后调用宿主接口清除本机会话。凭据与结果不进入聊天、模型或会话条目；`/bangumi-login`、`/bangumi-logout` 命令仍保留（终端版与手动输入可用，手动 `/bangumi-login` 同样是单个凭据弹窗）。`/bangumi-login-status` 查看已保存的登录元数据。
- 网络线路：设置弹窗「代理端口」行只显示两件事——配置项（**自动发现** / **直连** / **手动指定**）与代理地址，编辑弹窗里也只有这两项。切换立刻作用于模型请求、Bangumi 工具请求（宿主会重启本地 MCP 子进程，因为线路写在子进程的环境变量里）与之后的登录；改动**只在本次运行内生效**，重启后回到启动时的线路。与模型密钥同一套语义。
- 界面只有浅色一套外观：没有深色主题、没有主题切换，也不跟随系统偏好。

模型密钥可以在浏览器里直接填入：点侧栏底部用户行的齿轮「设置」入口（主界面没有顶栏），在「模型配置」行点「编辑」，选择提供方并填 API Key。密钥只注入宿主**本次运行**的运行时凭据，**不写入磁盘**（也不写 `models.json`、`auth.json` 或浏览器存储），进程重启后需要重新填写；应用后如果当前模型不可用，宿主会兜底切换到该提供方的第一个模型，之后可在「模型选择」行显式切换。密钥不进入会话条目与日志，回执里只出现提供方名称。

只改界面时用 `npm run build:web` 重建；`npm run dev:web` 同时启动宿主与 Vite 开发服务器，前端修改通过 HMR 热更新，`/api` 代理给宿主。先执行 `npm run build` 生成宿主产物；改动宿主代码后需要重新构建并重启。开发启动器默认直连，可用 `--proxy` 指定代理或 `--auto-proxy` 自动发现。`npm start -- web` 使用构建产物。停止服务用 `Ctrl+C`。

开发知识库入口见 [AGENTS.md](AGENTS.md)。会话可并行运行，切换只改变当前查看对象；草稿按会话保存。历史列表优先显示「待确认 / 待登录 / 运行中 / 当前」，其余会话显示相对时间。确认卡在工具运行期间仍可点击，仅应答请求在途时禁用。

下文提到的路径均相对仓库根目录。

## 界面风格

风格名是「**分层表面 + 弹性动效**」：结构上清晰直观，视觉上克制而精致——层级由强对比文字阶梯与主色点睛建立，而不是靠装饰。

> **这一节只讲结论。外观的唯一事实源是设计决策记录**：`web/docs/design/decisions.md`（总表与进度）与 `web/docs/design/decisions/G-tokens.md`（令牌总表），验收标准是与 `web/docs/design/index.html` 里的样张逐项一致。改外观前先读它们，口径冲突时以决策记录为准；开发知识库见 [AGENTS.md](AGENTS.md)。
>
> ⚠️ **`web/docs/design/` 整棵目录被 `.gitignore` 忽略**，**新克隆的仓库里没有它**——这些文件只存在于本机工作树。引用它们时请按「本地开发资产」理解。

- 配色以**粉色与白色**为两色核心：主色 `#ec6570`（HSL 355 78% 66%）用于选中态与强调，表面与描边全部由它用 `color-mix()` 就地派生，**页面不出现中性灰表面**（页面底与侧栏是极浅粉，对话区与内容区纯白，卡片与浮层是更浅一档的粉）；文字仍是中性深色，语义色（交互蓝 `#369cf8`、链接蓝 `#0084b4`、危险红、成功绿、警告黄、焦点环）保持原值。主色本身的白字对比度只有约 3.1:1，所以实心按钮另取加深一档的 `--bgm-primary-deep`（≈4.7:1，达到 AA）。
- **表面按内容类型分配装饰预算**（本项目最重要的一条外观判断）：**浮起层用玻璃**（输入卡、命令候选、思考强度菜单、统计浮层、弹窗、Toast、首屏示例 chip；同时出现的模糊层不超过 3 个）、**只有数据可视化用柔光**（统计条形与进度条的渐变填充 + 端点高光 + 光晕）、**文本密集类与内容卡片一律素**（纯色 + 描边 + 留白 + 字重）。**装饰性径向底光与环境光已全部删除**，面板底只用纯色阶梯（页面底 / 内嵌块 / 卡片浅面 / 白面四档）。
- 圆角只有四档：单元格 8 / 控件 10 / 容器 14 / 浮层 18（`--app-radius-cell/-control/-panel/-float`），**元素越小圆角越小**；胶囊与正圆退出超椭圆。超椭圆曲率 `superellipse(1.4)` 由 `tokens.css` 的 `*, *::before, *::after` **一处统一下发**（`--dsw-corner-shape`）——这是全项目唯一保留的上游令牌，不要在浮层或别处再声明一次。
- 结构是**两列**布局：**主界面没有顶栏**，外壳全部由侧栏承载（品牌行 + 连接状态点 + 折叠钮 + 实心主色的「开启新对话」+ 按「今天 / 更早」分组的会话列表 + 底部用户行与齿轮设置入口）；侧栏与对话区**同为白面**，两者靠侧栏投出的一条向右发散阴影（`--app-shadow-edge`）分区。对话区**没有粘性会话头**（已按设计决策删除）；输入卡只留输入与发送，思考强度与读数在卡外一行。
- 文字用**强对比阶梯**：字号阶梯四档（21/19/18/14px 打包字重与行高），正文 14px/1.72，标签走 `--app-font-tiny`；字体栈由 `--bgm-font` 一处定义（Windows 走系统 UI 字体，中文兜底由字体栈本身保证）；代码字体栈末尾补中文兜底，不让「等宽」把中文交给宋体。中文不使用「小号 + 宽字距大写」那套拉丁标签写法。
- 动效**明显弹性但有面积纪律**：悬停抬升与按下回位走 `--app-ease-spring`（大面积的浮层用它的收敛版 `--app-ease-spring-soft`），列表逐项入场 55ms 错峰（只给短列表），浮层从结构决定的方向展开；三条入场路径（挂载即入场 / 滚动容器内的行 / 滚进视口浮现）共用同一批时长、曲线、位移与错峰令牌，并全部尊重 `prefers-reduced-motion`。动效只动 `transform` / `opacity`（少量 `filter`、`background-position`），**不做 layout 动画**。
- 连接状态是侧栏品牌行里的 **8px 状态点**（取语义色），不再是一枚带文字的 chip。
- 弹窗沿用 bgm.tv 弹窗的语汇（源码 `.modal-panel` / `#TB_window` / `input.inputtext` 实测）：**玻璃面 + 浮层圆角 + `--app-shadow-float`**，**无蒙层**——弹窗的层次由自身的玻璃填充、背后那一片模糊与扩散阴影表达；整屏层只负责定位、居中与接住外部点击（点外关闭）。**弹窗不做 `opacity` 淡入**：`opacity < 1` 会让 `backdrop-filter` 失效，进出动画改由 `modal.css` 的 CSS keyframes 给、只动 `transform`。
- 弹窗标题栏固定 **40px**：左对齐的标题 + 右侧 30×30 点击区里的细线 ×，下面压一条 1px hairline；分类标签（如「设置」）退成标题前的一枚次级字，与标题重复时不再渲染。
- 弹窗内容区字段名是控件上方的次级字；输入框是独立描边控件（10px 圆角 + 1px 输入描边），聚焦走主色边框 + 3px 主色光晕；选项行是横排原生控件 + 1px 收尾线。弹窗按钮走同一套按钮基元（主按钮是加深底的粉底白字，次要按钮是淡底弱字），底部操作区上方压一条 1px hairline。
- toast 是玻璃胶囊，与弹窗同一语汇；同一时刻只保留一个弹窗，会话弹窗与设置弹窗不叠加。
- 会话流里的宿主提示（`notice` / `error` 条目）用行内语汇：提示是淡底无描边的一行说明，错误是状态点 + 文本，都不是整条彩色横幅。
- **只有浅色一套外观**：没有深色令牌、没有主题切换，也不跟随系统偏好。
- 保留可见焦点环，所有关键信息不依赖 hover 才能看到（这两条是刻意规避站点自身的可用性问题）。

落地位置：外观令牌在 `web/src/styles/tokens.css`（`--app-*`）与 `web/src/styles/bgm.css`（`--bgm-*`，**只有令牌定义，不含形态规则，也不做别名重定向**——上游 `--dsw-*` / `--dsh-*` 已在第七轮整体删除）；跨入口共享的表面原语在 `web/src/styles/common.css`。各文件的职责与引入顺序见 [AGENTS.md](AGENTS.md) §索引「样式文件的职责与引入顺序」。

## 内容组件库

除了纯文本回答，协议还预留了 12 个内容条目用于多样化展示：条目网格/列表、统计与评分直方图、进度与章节网格、键值信息栏、结构化表格、时间线、标签云、横向封面列表、修改前后对比、引用块、四态提示、链接列表。

它们的类型定义在 `bangumi/src/web/protocol.ts`（`MessageBlock` 的 12 个 kind），实现在 `web/src/components/content/`，样式在 `web/src/styles/content.css`。渲染入口只有一个：`web/src/components/content/MessageBlocks.tsx`——流式区（`conversation/Streaming.tsx`）与历史条目（`conversation/Turn.tsx`）都必须把块数组交给它，工具行展开体也走同一个入口。

**组件库文档是应用内的一个入口**：`web/library.html`（开发时 `http://127.0.0.1:5173/library.html`）。它是**自绘骨架**，与主界面、调试页共用同一套令牌与共享组件（顶栏 `AppTopBar`、导航行 `.appNavRow`、胶囊 `Pill` 等），**不再依赖任何 UI 框架**：**左侧常驻导航**（两层分组 + 搜索过滤，当前项粉底 + 左侧主色条）、**中间详情**（真实 `ContentBlock` 渲染的 UI 预览 + 主载荷与空数据两张卡、参数表、可直接粘进调试页的 event 与 frame JSON）、**右侧自绘目录**（`PageToc` + `IntersectionObserver`；不用 hash 锚点，因为「一组件一页」的路由占着 hash）。总览页是每种条目一张卡，卡里也是真实渲染。一组件一页的地址形如 `library.html#/components/DataTable`，可直接分享与刷新；配色仍是项目令牌，只渲染浅色一套。

宿主已产生这些条目（`bangumi/src/web/message-blocks.ts` 与 `tool-view.ts` 做投影），在帧的 `items` 里下发对应 `kind` 即可生效，不需要改前端。

## 验证

**本节只保留参考点仍然成立的结论。** 界面重构（第七轮，2026-10-06）之前的实测明细——顶栏连接 chip、粘性会话头、旧弹窗的 `getComputedStyle` 数值、`TurnView` / `ToolActivity` 一代的渲染核对——**均已作废，不再列在本文件**，需要回溯时用 `git log -- web/README.md` 看历史版本。当前回归用例见 [AGENTS.md](AGENTS.md) §索引「改动完成后回归验证」，外观验收以 `web/docs/design/index.html` 的样张为准。

在 `bangumi/` 执行 `npm run typecheck` 与 `npm run build`。仍然成立的实测：

- **接口与鉴权**：令牌换 Cookie、无凭据 401、越权 Host 403、路径穿越 404、超长输入与未知端点 400、静态资源与 CSP。
- **浏览器交互**：斜杠命令列表与补全、扩展命令执行与结果回显、登录弹窗与取消往返、历史会话列表与会话切换、新建会话与条目重建、多标签页同步。
- **对话与工具链路**：用 Pi 自带的 `faux`（脚本化响应）Provider 替换模型、用本地假客户端替换工具上游，其余（Pi 运行时、会话、Web 会话层、HTTP/SSE、前端）全部为真实实现，在浏览器里跑通了「用户消息 → 工具调用 → 过程条目 → 模型继续回答」，并确认会话落盘、历史会话恢复与条目编号在切换后继续递增。
- **操作授权**：授权判定与执行全在宿主，浏览器只提交命令与展示结果；待授权只在输入区呈现一次，历史模式只呈现结果。「没有已连接的浏览器时拒绝写入」也由宿主负责。
- **思考强度**：级别与中文名由宿主按模型能力下发，浏览器不维护副本；不支持思考的模型与「尚未选择模型」是两种不同的置灰原因（后者靠 Pi 的 `unknown` 占位模型识别）；选定后写进隔离目录 `pi/settings.json` 的 `defaultThinkingLevel`，重启后新会话沿用。
- **会话输出展示**：思考随轮次落条目（历史里也在）、工具升级为结构化条目（中文标题 / 工具族 / 参数摘要 / 参数原文 / 结果内容块 / 耗时 / 读写）、轮次边界由宿主下发、折叠统一走 `hidden="until-found"`（Ctrl+F 能命中折叠内容并自动展开）。用改造前产生的旧会话回溯验证过 13 轮思考行与 7 个工具行全部还原。
- **流式输出**：宿主改增量帧、SSE 合并窗口 16ms，前端逐字摊平与收尾播放（实测 59.5 字/秒），会话区贴底跟随改 `ResizeObserver`（生产构建下浏览器长任务 24 个/轮 → 0 个）。逐字摊平在注入帧下完整验证；真实 SSE 帧下的端到端一轮仍待复测。

**未验证**：真实模型提供方的流式与工具组合、真实 Bangumi 账户下的写入提交与独立回读、登录成功后的在线核实、写入确认卡接管（需要宿主发起一次真实写入流程，自动化里无法安全触发）。其中两条环境限制另见 [AGENTS.md](AGENTS.md) §现状「已知未做 / 未验证」。
