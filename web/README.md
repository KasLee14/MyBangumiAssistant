# Bangumi 助手 Web 终端

需要浏览器界面时启动 Web 终端；它与终端版共用同一套 Pi 会话、工具与授权判定，浏览器只提交命令与展示宿主生成的文本：

```powershell
npm start -- web --port 8787
```

启动后打印一个带一次性令牌的地址，并自动用默认浏览器打开：

```text
Bangumi 助手 Web 终端：http://127.0.0.1:8787/?token=<一次性令牌>
```

浏览器用该令牌换取 HttpOnly Cookie 后地址栏回到 `http://127.0.0.1:8787/`。服务只监听回环地址并校验 `Host` 与访问凭据，用 localhost 直连但没有凭据同样返回 401；带令牌的地址等同本机访问权，不要分享。`--no-open` 只打印地址，端口被占用时向后顺延并打印实际端口。

界面能力：

- 对话与流式输出、思考过程折叠块、可折叠的工具活动（`/details` 展开或收起）。
- 斜杠命令补全：本地命令（`/help`、`/new`、`/model`、`/sessions`、`/details`、`/exit`）与 Pi 已注册的扩展命令（`/bangumi-login`、`/bangumi-login-status`、`/bangumi-logout`）合并展示。
- 模型切分两步：设置弹窗的「模型配置」行填 API Key、「模型选择」行切模型，两者不能在同一次提交里完成。只有宿主报告了可用模型（某个提供方的凭据已配置）时，「模型选择」的编辑才可点，否则置灰并提示「请先完成模型配置」。历史会话在左侧栏，可新建或在列表里恢复（`/model`、`/sessions` 分别直达模型选择弹窗与会话弹窗）。
- 思考强度：输入卡右侧常驻一枚「思考 · 高」式标签，点开就地选择。可选级别与中文名全部由宿主按 Pi 的模型能力下发，浏览器不维护副本——`deepseek/deepseek-flash` 是 `off/low/high/max`，`deepseek/deepseek-v4-pro` 只有 `off/high/max`，未选择模型或当前模型不支持思考（`reasoning` 为 false）时标签置灰并说明原因。**这是界面里唯一会写本机 Pi 配置的切换**：选定后立即写进隔离目录 `pi/settings.json` 的 `defaultThinkingLevel`，重启后新会话沿用该级别（恢复旧会话时以该会话里的级别变更记录为准）；已经发出的那一轮请求参数不变。菜单向上展开，Esc 只关菜单，不会顺带停止本轮或拒绝确认。
- 写入确认：所有写入经当前宿主的 `execute_write_batch` 完整计划入口。普通单项免二次确认，发布或修改非空作品短评、全部批量类别展示中文完整范围并确认一次；全部无需修改时不提交。确认卡的标题和按钮由宿主按计划生成，提交前重新核对账户、真实输入与网站现状，写后独立回读。**没有已连接的浏览器时宿主直接拒绝写入**，不会挂起等待；连接在提交前断开则停止，已提交步骤仍独立核查，未知不重发。
- Bangumi 登录：设置弹窗「登录状态」行只显示是否登录——未登录时给出「登录」，已登录时显示已保存的用户名与「退出登录」。两者都在弹窗里完成，**不再向会话发送 `/bangumi-login`、`/bangumi-logout`**：登录弹窗一次填邮箱与密码，提交后弹窗保持打开显示宿主下发的进度（人机验证在系统默认浏览器完成），成功后自动关闭、失败则留在弹窗内可改密码重试，关掉弹窗即中止这次登录；「退出登录」先给出确认弹窗，确认后调用宿主接口清除本机会话。凭据与结果不进入聊天、模型或会话条目；`/bangumi-login`、`/bangumi-logout` 命令仍保留（终端版与手动输入可用，手动 `/bangumi-login` 同样是单个凭据弹窗）。`/bangumi-login-status` 查看已保存的登录元数据。
- 网络线路：设置弹窗「代理端口」行只显示两件事——配置项（**自动发现** / **直连** / **手动指定**）与代理地址，编辑弹窗里也只有这两项。切换立刻作用于模型请求、Bangumi 工具请求（宿主会重启本地 MCP 子进程，因为线路写在子进程的环境变量里）与之后的登录；改动**只在本次运行内生效**，重启后回到启动时的线路。与模型密钥同一套语义。
- 界面只有浅色一套外观：没有深色主题、没有主题切换，也不跟随系统偏好。

模型密钥可以在浏览器里直接填入：点顶栏右侧的设置图标，在「模型配置」行点「编辑」，选择提供方并填 API Key。密钥只注入宿主**本次运行**的运行时凭据，**不写入磁盘**（也不写 `models.json`、`auth.json` 或浏览器存储），进程重启后需要重新填写；应用后如果当前模型不可用，宿主会兜底切换到该提供方的第一个模型，之后可在「模型选择」行显式切换。密钥不进入会话条目与日志，回执里只出现提供方名称。

只改界面时用 `npm run build:web` 重建；`npm run dev:web` 同时启动宿主与 Vite 开发服务器，前端修改通过 HMR 热更新，`/api` 代理给宿主。先执行 `npm run build` 生成宿主产物；改动宿主代码后需要重新构建并重启。开发启动器默认直连，可用 `--proxy` 指定代理或 `--auto-proxy` 自动发现。`npm start -- web` 使用构建产物。停止服务用 `Ctrl+C`。

开发知识库入口见 [AGENTS.md](AGENTS.md)。会话可并行运行，切换只改变当前查看对象；草稿按会话保存。历史列表优先显示「待确认 / 待登录 / 运行中 / 当前」，其余会话显示相对时间。确认卡在工具运行期间仍可点击，仅应答请求在途时禁用。

下文提到的路径均相对仓库根目录。

## 界面风格

界面沿用 bgm.tv 的视觉语汇（依据 `docs/bgm-design/ui-style.md` 与 `interaction-style.md` 的实测数据，静态预览见 `docs/bgm-design/style-preview.html`）：

- 粉色主色 `#f09199` 用于选中态与强调，交互蓝 `#369cf8` 用于 hover，标签是描边蓝字胶囊、选中反转为主色实心。
- 卡片是 1px 边框 + 10px 圆角、**无投影**（靠边框分组）；列表分类用实线、条目用点线；下拉与列表行的 hover 是整行填充交互蓝 + 白字。
- 连接状态 chip 用语义底色直接表态：已连接是绿底绿字、连接中断是红底红字，不靠一个 6px 圆点。
- 顶栏右侧的设置入口沿用原模型按钮的六边形图标。
- 弹窗按 bgm.tv 弹窗的实测值重做（源码 `.modal-panel` / `#TB_window` / `input.inputtext` + 收藏弹窗截图比对）：**15px 圆角 + `0 5px 30px 10px rgba(80,80,80,.5)` 大扩散柔光**，表面是与站点一致的浅色玻璃（`rgba(254,254,254,.8)` + 20px 背景模糊），遮罩只压到 `rgba(0,0,0,.1)`。
- 弹窗标题栏固定 **40px**：左对齐的 16px/700 主色标题 + 右侧 30×30 点击区里的 **15px 细线 ×**（`#ccc`，hover 转黑，无边框无底色），下面压一条 1px `#eee` 实线；分类标签（如「设置」）退成标题前的一枚 12px 灰字，与标题重复时不再渲染。
- 弹窗内容区 15px 内边距：字段名是控件上方的 12px 灰字；输入框是 5px 圆角 + 1px `#d9d9d9` 的独立描边控件，聚焦走粉色边框 + 内阴影 + 主色外发光；选项行（网络线路三选一等）是横排原生控件 + 1px `#eee` 实线收尾，对应站点收藏弹窗的「想看 / 看过 / 在看 / 搁置 / 抛弃」那一行。
- 弹窗按钮：主按钮是 14px 白字粉色胶囊（`5px 25px` 内边距），次要按钮是 `#eee` 底、`#888` 字的灰色胶囊，hover 都落到交互蓝；底部操作区不带分隔线。
- toast 仍是浅色胶囊，与弹窗同一语汇；同一时刻只保留一个弹窗，会话弹窗与设置弹窗不叠加。
- 会话流里的宿主提示（`notice` / `error` 条目）改用 deepseek-harness 的行内语汇：提示是淡底无描边的一行说明，错误是状态点 + 文本，两者都不再是整条彩色横幅；三段式语义底色只留给正文里的提示块。
- 只保留浅色一套外观：没有深色令牌、没有主题切换，也不跟随系统偏好。
- 字体改用系统 UI 字体栈；正文 14px、辅助信息 12–13px（不采用站点的 12px 正文基准）。
- 保留可见焦点环，所有关键信息不依赖 hover 才能看到（这两条是刻意规避站点自身的可用性问题）。

落地方式见 `web/src/styles/bgm.css`：它重定向既有语义令牌并覆盖组件形态，不改动既有布局规则。

## 内容组件库

除了纯文本回答，协议还预留了 12 个内容条目用于多样化展示：条目网格/列表、统计与评分直方图、进度与章节网格、键值信息栏、结构化表格、时间线、标签云、横向封面列表、修改前后对比、引用块、四态提示、链接列表。

它们的类型定义在 `bangumi/src/web/protocol.ts`（`TranscriptItemView` 的 12 个 kind），实现在 `web/src/components/content/`，样式在 `web/src/styles/content.css`，接入点在 `web/src/components/TurnView.tsx`。

**组件库文档见 `docs/bgm-design/component-library.html`**（自包含，双击可看）。它采用 Ant Design 组件文档页的布局与交互：**左侧常驻导航**（搜索框 + 分组组件列表，当前项高亮）、**中间详情**（渲染示例、从协议逐字摘录的 TypeScript 类型、完整示例 JSON、接入说明）、**右侧锚点目录**（随当前详情生成，点击滚到对应分块）；「组件总览」一项显示分组卡片网格。点击左栏即可切换右侧内容，`#sec-subjects` 这类地址可直接分享与刷新定位；配色仍是 Bangumi 令牌，示例只渲染浅色一套。文档由同目录的 `component-library.template.html` + `build-component-library.py` 生成，改内容改模板再重新 build，类型与 CSS 会自动同步。

宿主当前不产生这些条目，浏览器已经能渲染——在帧的 `items` 里下发对应 `kind` 即可生效，不需要改前端。

在 `bangumi/` 执行 `npm run typecheck` 与 `npm run build`。Web 终端已验证的部分：

- **接口与鉴权**：令牌换 Cookie、无凭据 401、越权 Host 403、路径穿越 404、超长输入与未知端点 400、静态资源与 CSP。
- **浏览器交互**：斜杠命令列表与补全、扩展命令执行与结果回显（`/bangumi-login-status`、`/bangumi-logout`）、登录弹窗与取消往返、历史会话列表与会话切换、新建会话与条目重建、多标签页同步。
- **对话与工具链路**：用 Pi 自带的 `faux`（脚本化响应）Provider 替换模型、用本地假客户端替换工具上游，其余（Pi 运行时、会话、Web 会话层、HTTP/SSE、前端）全部为真实实现，在浏览器里跑通了「用户消息 → 工具调用 → 可折叠工具活动（含失败态与详情）→ 模型继续回答」，并确认会话落盘、历史会话恢复与条目编号在切换后继续递增。
- **写入确认**：确认卡的渲染与回执交互（待确认/已确认/已拒绝、预览全文、确认与取消按钮）以及「没有已连接的浏览器时拒绝写入」的判定。
- **本轮改版**：在本机浏览器里核对了浅色单外观（无深色属性、无含 `dark` 的样式选择器）、侧栏只剩新建会话与历史会话、顶栏只剩连接状态与六边形设置图标、连接状态 chip 的绿/红语义底色与状态点、设置弹窗三行（模型 / 代理端口 / 登录状态）、模型与密钥弹窗的提供方与模型选择、代理端口弹窗的自动发现/直连/手动三选一，以及 `/model` 直达模型与密钥弹窗。
- **弹窗改版**：在本机浏览器里逐个打开了设置、模型与密钥、网络线路、历史会话、Bangumi 登录五个弹窗（登录弹窗在取消后由宿主确认「登录已取消」），用 `getComputedStyle` 核对关键值——480px 宽 / 15px 圆角 / `rgba(80,80,80,.5) 0 5px 30px 10px` 阴影 / 玻璃面 `rgba(254,254,254,.8)` + `blur(20px)` / 40px 标题栏 / 16px-700 主色标题 / 30×30 细线关闭按钮 / 34px 高、5px 圆角、`#d9d9d9` 描边的输入框 / 32px 胶囊按钮——并确认设置弹窗与会话弹窗不再叠加、`npm run typecheck` 通过。
- **设置弹窗拆分**：在本机浏览器里核对了拆分后的四行（模型配置 / 模型选择 / 代理端口 / 登录状态）、模型配置弹窗只剩提供方与 API Key、代理弹窗只剩配置项三选一与代理地址、`/model` 在已解锁时直达模型选择弹窗、子弹窗关闭后回到设置行；用一次性假 Key 让 deepseek 进入「本次运行已填入」后，确认「模型选择」由置灰变为可点、下拉里是 `deepseek/deepseek-flash（当前）`，且设置行在应用密钥后自动刷新（宿主兜底切到该提供方第一个模型）。
- **登录改走弹窗**：用一份真实的已登录数据目录启动，确认设置弹窗「登录状态」行显示用户名 `630841` 与「退出登录」（原来只在 `agent_settled` 刷新、登录命令不产生 agent 轮次，所以显示不出来）；另用 `--data-dir` 指向一次性空目录启动第二个实例，核对了未登录态、登录弹窗的邮箱+密码一次提交、提交后的进度展示（弹窗保持打开显示宿主下发的「请在默认浏览器完成 Bangumi 人机验证…」，页脚只剩「取消」）与取消后的状态复位（`/api/state` 读回 `loginBusy=false`、`loginStatus=""`）；手动 `/bangumi-login` 也确认只弹一个凭据弹窗。`npm run typecheck`、`npm run build` 通过。
- **思考强度**：用一次性数据目录（`--data-dir`，`pi/models.json` 只放 deepseek 的占位密钥）启动，核对了标签按模型能力列级别——`deepseek-v4-pro` 只有「关闭 / 高 / 最高」，切到 `deepseek-flash` 后出现「低」；选中「最高」后标签与宿主提示同步更新，隔离目录的 `settings.json` 写入 `"defaultThinkingLevel": "max"`；重启同一数据目录后新会话的当前级别仍是「最高」，说明它来自磁盘默认值而不是上一轮会话。另用 `POST /api/thinking` 提交当前模型不支持的 `low`，得到 400 与「思考强度只能是 关闭（off）、高（high）、最高（max）。」；切到不支持思考的 `openrouter/deepseek/deepseek-chat` 后标签变成置灰的「思考 · 不支持」；再用 `--data-dir` 指向一个没有任何凭据的空目录启动，标签是置灰的「思考」并提示「尚未选择模型，无法设置思考强度」——Pi 在没有可用模型时会挂一个 provider/id 都是 `unknown` 的占位模型，宿主按这个特征区分「没选模型」与「模型不支持思考」。`npm run typecheck`、`npm run build` 通过。

**未验证**：真实模型提供方的流式与工具组合、真实 Bangumi 账户下的写入提交与独立回读、登录成功后的在线核实。本次改版实测覆盖了登录弹窗的输入、进度、取消与状态复位，以及「已登录」元数据的显示，但**没有完成一次真实登录**（成功路径需要你的邮箱与密码），也没有点下「退出登录」的确认按钮（会清除你本机保存的会话）；这两步留给你实测。其余需要真实模型密钥的部分仍属本机验收范围。
